# Proposed course: Building and Evaluating AI Applications

An illustrative 15-week, three-credit computing elective. The college would agree credits, prerequisites, contact time, final outcomes, and assessment rules. This is a proposed course outline. The complete offline evaluation-and-revision unit is included; the other lessons, live adapter, and complete semester materials are not.

## Intended students and foundations

Students should already be comfortable writing and debugging a small program, working with structured data, and using basic Git. The reference language is Python. A supplied application scaffold keeps the required work focused on retrieval, model integration, evaluation, and maintenance. A readiness task and refresher address gaps before the capstone.

Introduce training versus inference, classification, embeddings, retrieval, and language-model limitations. A short instructor-led classification exercise uses synthetic support requests. It is not another capstone. The elective focuses on building applications with generative AI; it is not a comprehensive AI or machine-learning survey.

## Outcomes and evidence

| Outcome | Evidence |
| --- | --- |
| Build retrieval and model-backed paths that preserve sources | Working implementation, source records, integration checks |
| Compare generated answers with ordinary search | Evaluation cases, annotated outputs, justified recommendation |
| Diagnose and revise failures | Reproduced failure, implementation change, regression test |
| Explain and maintain the work | Individual demonstration, reproducible handoff, change record |

Both approaches must be implemented and evaluated. A justified decision to retain ordinary search may earn full credit after the required work is demonstrated. The live integration outcome requires institution-approved model access arranged before delivery.

## Proposed sequence

| Weeks | Focus | Student evidence |
| --- | --- | --- |
| 1–3 | Readiness, AI foundations, problem definition, guided classification | Readiness task, problem brief, error explanation |
| 4–6 | Documents, versions, retrieval | Search baseline and initial tests |
| 7–9 | Model integration, answer structure, citations, missing information | Model-backed application and comparison examples |
| 10–12 | Evaluation, failures, accessibility, cost and response time | Evaluation report and targeted improvements |
| 13–15 | Revision, individual demonstration, handoff | Reproducible submission and maintenance plan |

The included public unit is an adaptable example for the evaluation and revision portions. Advanced deployment and more complex retrieval are optional extensions. No claim is made that this schedule has been piloted.

## Evaluation design

Use the same source collection and questions when comparing search with generated answers. Initially keep retrieval fixed so changes in generation can be interpreted. Evaluate usefulness, source support, appropriate answering/referral, and repeated-run variation. Record cost and latency separately from quality.

Retain inputs, source versions, provider/model configuration, dated outputs, and scoring notes for actual runs. Replaying archived outputs can reproduce scoring; fresh model calls may differ. The four public fixtures are designed for discussion and do not establish general reliability or benchmark accuracy. Faculty would prepare additional unseen cases and disclose the categories and grading criteria before assessment.

## Adoption and continued revision

Agree faculty preparation, supported environment, approved model access, usage limits, support, and accessible assessment before delivery. During outages, preserve the opportunity to demonstrate live integration rather than silently substituting authored replay.

Review tools, models, source content, costs, faculty feedback, assessment evidence, and relevant workplace needs. Record approved revisions and remaining priorities. In an Annual Curriculum Partnership, covered courses/program, revisions, consultation, schedule, and fee are agreed before work; additional work is scoped separately.
